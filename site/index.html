THE ENGINEERING PROBLEM

The difficult part is
knowing what you know.

A storefront, a promotion claim, and a route are different kinds of records. Treating them as one makes every correction harder.

HGC separates location snapshots from offer observations, preserves source and review context, and applies explicit rules before generating a view. A retailer-reported claim stays distinct from independent verification.

The same bridge pattern used for the event project now feeds this showcase. A small allowlisted projection carries public facts into the view while provider coordinates and private operational data stay out.

DESIGN DECISIONS

Small distinctions.
Stronger systems.

01

Evidence travels with the claim.

Source type, observation time, evidence references and verification state are part of HGC’s offer contract. A retailer assertion does not become an independently verified result.

02

A comparison metric stays labeled.

The route engine can use Haversine distance or a supplied travel matrix. Haversine is straight-line comparison distance. This showcase includes no Google matrix, road geometry, or geocoded dataset.

03

The catalog is bigger than one itinerary.

In the inspected implementation, group-wide constraints affect a route’s selected representative without removing alternate storefronts from the public catalog.

04

Reproducible decisions need precise language.

Fixed inputs and tie rules yield deterministic route decisions. Production output includes a generated timestamp, so byte-identical JSON is not promised.
